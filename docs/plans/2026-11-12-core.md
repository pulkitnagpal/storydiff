# Storydiff core (module 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A TypeScript npm package `storydiff` that parses language v0.3, renders the review card exactly as on the canvas boards, checks every claim, and ships the CLI (`check`, `render --html/--png/--md`, `view`, `publish`).

**Architecture:** Pure modules: `spec` (text to doc), `render` (doc + captures + report to HTML or Markdown), `check` (doc + git + tests + session log to report). A thin `cli` wires them to files in `.storydiff/` and to `gh`. `shot` drives headless Chromium over CDP for PNGs. It is shared with the capture module. Tests run straight from `.ts` with `node --test`. esbuild bundles `dist/cli.js` for npm.

**Tech Stack:** TypeScript (type stripping only, so no enums, namespaces or parameter properties), Node 22+ built-ins (`node:test`, `node:child_process`, `node:util` parseArgs), esbuild and typescript as dev dependencies. No runtime dependencies.

**Spec:** `docs/v1-build.md` (locked). The truth for looks is `poc/v3/canvas/*.dc.html`. The ports start from `poc/v3/spec.js`, `poc/v3/render.js`, `poc/v3/shot.js` and `poc/verify.js`.

## Global Constraints

- The output must match the canvas: a test renders the four fixtures and compares them with `poc/v3/canvas/{Card,CardInfra,CardRefactor,CardBig}.dc.html`.
- Never draw a pin whose target was not found. Never fake slot 3.
- The captures contract is `.storydiff/captures.json` = `{ "shows": [...] }`, one entry per `show` line, in order, shaped as in `docs/v1-build.md`.
- The report contract is `.storydiff/report.json` = `{ oldPass, newTests, regressed: string[], claims, failed, checks: [{ ref, kind: "proof"|"said", ok, why, at? }] }`. Optional extras: `base`, `head`, `session`.
- Node 22+, MIT licence, no runtime npm dependencies.
- Personal GitHub only: `env -u GITHUB_TOKEN gh …`. Never push.
- No local paths or personal details in committed fixtures. The session logs are scrubbed of system-reminder turns.
- This module owns only `src/spec`, `src/render`, `src/check`, `src/cli`, `src/shot`, `src/index.ts`, `test/`, the package files and `docs/plans/`. Leave `src/capture`, `plugin/`, `action/` and the README alone.
- Grammar changes go in `src/spec`, one small, named change each, recorded in `docs/plans/core-notes.md` for the other sessions.

## Review Focus

1. **A spec with a show line but no capture for it** (capture not run yet, or it failed). Expected: the card renders without slot 3 for that show, prints a warning, and never crashes. Test: `render skips a show with no capture` (Task 3).
2. **A screen pin whose selector was not found** (`found: false`). Expected: no pin is drawn. Test: `screen pins only where found` (Task 3).
3. **A failing check or a regression.** Expected: the verdict turns red ("✗ 2 old tests now fail", "✗ 3 of 29 claims don't hold up"), the CLI exits 1, and the Markdown shows it. Test: `verdict shows failures` (Task 3), `check exits 1 on a fake claim` (Task 5).
4. **The session log has meta, tool and system-reminder turns.** Expected: only words the human typed can match a `said`. Test: `system reminders are not the human` (Task 4).
5. **The PR body already holds a storydiff block.** Expected: publish replaces it in place and keeps the rest of the body. Test: `upsert replaces the old block` (Task 6).

**Signature (the comparison):** `cardSignature(html: string)` parses with a tiny tag walker. It returns:
- the header, nav and section texts;
- the `.lbl` texts in order;
- the `.vt` texts;
- the `.li` texts;
- the `.json` texts with pins removed;
- the `.same` and `.sr` texts;
- the `.stp`, `.rr`, `.fr` and `.oc` texts;
- every pin as a tone and number (a sorted multiset);
- per strip: boxes as `label|state|left|top|width|height`, pins as `tone|n|left|top`.

Whitespace is ignored in texts. Positions match within ±4 px, except screen pins, which come from the real screenshot (tone and number only). State and tone come from a class or from the inline colour, so canvas markup and generated markup compare alike.

- a row with a noted box uses `W=[120,118,120]`, `X=[10,172,330]`; the noted box is 62 tall and the others sit at `top 32`;

- pins never go left of 0;

### Task 9: Stress-test fixes from the starting session (real PRs: Python, Rust, a 46-file feature spread over 6 repos)

Every item is must-fix. Grouped by module and done test-first, one commit per group.

**9a. Spec grammar** (`src/spec`):
- `smaller "one line" files a.ts, b.ts` gives `doc.smaller: { line, files }[]`.
- Mark `x`, "breaks for callers", gives `mark: 'breaks'` and is listed first, in red. A line `x -> y` is still an arrow from box `x`.
- List numbering: breaks, then new/changed/gone, then kept, then watch. Only new, changed, gone and kept count toward the 7-item cap. Breaks and watch items are never dropped and are numbered past 7.
- `ask "…" from "who" in "#1484"` gives `doc.asks: { text, from?, in? }[]`, and `doc.ask` is the first ask. Later asks render as "then: …", up to 2.
- `by "Maya"` without `with` means `agent: ''`: a PR with no agent session.
- A box line can end with `in "repo#n"`, giving `Node.repo`.
- `pin before screen "…"` and `pin before line "…"` give `Pin.side: 'before' | 'after'`. `pin line "text"` is a new place, for terminal output.
- `run-tests "cmd"` gives `doc.runTests`. `run`, `setup`, `show same … {json}`, `show terminal` and scenario `do`/`then` are as in Task 8. The `{json}` tokenizer reads to the matching bracket.
- Chapters: a `chapter N` line at indent 0 starts that chapter's section. Lines before the first `chapter` are shared. `parse(src)` returns the first chapter, with `doc.rest: Doc[]` for the others. A chapter whose title starts with "+" needs no map.

**9b. Card** (`src/render`):
- **Honesty.** "Nothing to try", and "Nothing. Every reply matched…", appear only when there is at least one `same` capture and every one matched. Otherwise the card says "Nothing flagged", grey, with no ✓. When `unchecked` is true or a count is null, no chip gets ✓ or the green tone (it's grey with a dashed border instead). A `typed: true` capture gets an "illustrative · from code" stamp, plus a "not captured" verdict chip.
- **Header.** With no agent, drop "with …" from the header and "…'s session" from the footer, and the did label becomes "<by> did". `from`/`in` on an ask gives the label "DAVIDISM ASKED (#1484)".
- **Verdict chips.** Coverage: "✓ Covers all N changed files" or a red "✗ M files not covered". Edited old tests: "✎ N old tests edited" (watch tone). The watch chip also counts `!` items in "+" chapters (`doc.rest`).
- **List.** A "Breaks for callers" group comes first, in red. `smaller` lines fold into one dashed row, "+ N smaller changes". The card grows taller and never clips.
- **Pictures.**
  - Every kind guards null sides: `before: null` is the new form (the after alone, tagged NEW), and `after: null` is the removed form (the before alone, crossed out).
  - A terminal is two dark panels showing `$ cmd`, the last 12 lines and the exit code. After-lines not in before are highlighted, and `pin line` marks a line.
  - Screen pins with `side: 'before'` use `rectsBefore`. Capture is asked to write that field.
- **Map.** A box `in "repo#n"` is dashed, with a small repo tag. The X on a removed cross-row edge sits at the curve's real midpoint.
- **Text.** Code-like tokens (`--flags`, `a.b`, `path/x`, `fn()`) never break. Long outcome values shrink to fit their box.
- A "+" chapter's card is list-only (no slot 3, no map).

**9c. Checker** (`src/check`):
- **Coverage.** Every changed file has to be covered: by a `file:line` proof in it, by a `test` proof whose name appears in it, or by a `smaller … files` entry. These are ignored by default: `*.lock`, `package-lock.json`, `dist/**`, `*.snap`, `handover.storydiff`, `.storydiff/**`, plus the globs in `.storydiffignore`. The result is `report.coverage = { files, covered, uncovered: string[] }`, and uncovered files exit 1.
- **Quotes.** Leave out `<pasted_content>` blocks, fenced code, `> ` quote lines, paragraphs of 12 lines or more, compaction summaries (`isCompactSummary`, or "This session is being continued…") and tool results. The `ask` is checked as a quote unless it has `from`. Sessions longer than 24 h give quote times as "day N, HH:MM".
- **Test runners.** Detected from the manifest:
  - `Cargo.toml`: `cargo test`;
  - `pyproject.toml`, `setup.py` or `pytest.ini`: `python -m pytest -v -rA`;
  - `go.mod`: `go test -v ./...`;
  - `package.json`: `node --test --test-reporter=tap` when the test script is `node --test`, else `npm test`.

  `run-tests` in the spec, or `--test-cmd`, overrides that. One parser reads TAP, jest/vitest, cargo, pytest and go output. A test proof matches the exact name, or the last part of a qualified name (`::`, ` > `, `/`, `.`).
- **Edited old tests.** `report.editedOld: string[]` lists old tests whose assertion lines were removed or changed. Each is found from the nearest test declaration above the changed line in the base file.

**9d. CLI and package:**
- `storydiff capture` dispatches to `src/capture/cli.ts` when that file is present;
- add a `prepare` build step, with no postinstall and zero runtime dependencies;
- `test` also runs `test/capture` and `action/test` when present;
- `render` writes one card per chapter (`card.html`, `card-2.html`, …), and the Markdown covers them all.

Tests: one per bullet, named after the bullet, in `test/spec.test.ts`, `test/render.test.ts`, `test/check.test.ts` and `test/cli.test.ts`. `canvas.test.ts` stays green throughout.
